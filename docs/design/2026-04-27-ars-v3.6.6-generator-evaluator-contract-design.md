## §1 — Scope and Goals

### Target release

v3.6.6 (`academic-paper/full` writer/evaluator sprint contract)

**Roadmap anchor**: §3.6.4 description correction + §3.6.5 exit criteria last item
**Schema impact**: Schema 13.1 backward-compatible add. Schema 14 explicitly rejected per Approach 1 decision.

### In scope

1. `shared/sprint_contract.schema.json` Schema 13.1 upgrade:
   - `mode` enum adds `writer_full` + `evaluator_full`
   - New optional top-level fields: `pre_commitment_artifacts`, `disagreement_handling`
   - Reviewer-specific required fields gated behind `allOf` / `if mode startsWith reviewer_`, including `measurement_procedure.reviewer_must_output_before_paper`, reviewer scoring-plan requirements, `failure_conditions[].cross_reviewer_quantifier`, and editorial `failure_conditions[].action`
   - Writer conditional gate requires `pre_commitment_artifacts` for `writer_full`
   - Evaluator conditional gate requires `disagreement_handling` for `evaluator_full`
   - **Note**: `agreement_audit` is intentionally NOT a schema field. It is a runtime artifact (see item 10), not pre-registered acceptance criteria. Keeping it out of the schema preserves the v3.6.2 design philosophy that contract = "what good looks like before the work runs", not "what was observed during the work".

2. `shared/contracts/writer/full.json` + `shared/contracts/evaluator/full.json` contract templates.

3. `shared/contracts/README.md` update documenting writer/evaluator contract directories, mirroring v3.6.2 convention.

4. `scripts/check_sprint_contract.py` mode branching for reviewer, writer, and evaluator contracts; structure unchanged, logic extended.

5. `tests/test_check_sprint_contract.py` extension + CI coverage for `shared/contracts/writer/` and `shared/contracts/evaluator/`.

6. `academic-paper/agents/draft_writer_agent.md` Phase 4 hard gate:
   - Phase 4a paper-blind commitment: output `acceptance_criteria_paraphrase` + writer pre-commitment artifacts
   - Phase 4b paper-visible drafting against the Phase 4a commitments

7. `academic-paper/agents/peer_reviewer_agent.md` Phase 6 hard gate:
   - Phase 6a paper-blind commitment: output `contract_paraphrase` + evaluator scoring/disagreement commitments
   - Phase 6b paper-visible evaluation; verdict logic unchanged

8. `academic-paper` orchestration wiring for the actual two-call Phase 4 and Phase 6 split. The spec must name the orchestration file(s) that call `draft_writer_agent.md` and `peer_reviewer_agent.md`, or explicitly document that existing orchestration already supports separate paper-blind and paper-visible calls.

9. Model selection mirrors existing `ARS_CROSS_MODEL` env pattern: unset → warning + same-model; set → use that model ID for evaluator/cross-runtime comparison. No new env var.

10. Agreement audit split:
    - `academic-paper/references/agreement_audit_protocol.md` for the versioned protocol/template
    - `examples/ab_evidence/v3.6.6/agreement_audit_results.md` for runtime example output

11. A/B evidence in `examples/ab_evidence/v3.6.6/`:
    - AI-generated synthetic paper draft fixture
    - User verification before use
    - Human-authored defect injection
    - Human-authored `expected_findings.yaml`
    - Process-metric-only, delta-based comparison
    - Cross-runtime triangulation via Codex/GPT-5.4
    - Pre-declared directional hypotheses and initial ship thresholds: H1 scoring-plan adherence delta ≥ +20 pp; H2 score variance reduction ≥ 15%; H3 expected-defect catch-rate delta ≥ +2 findings or +20 pp, tuned after fixture sizing

12. ROADMAP §3.6.4 description correction + new decision-log entry recording that v3.6.6 extends contracts to the existing writer/evaluator pair, rather than splitting a single agent.

13. CHANGELOG / `.claude/CLAUDE.md` / README / `scripts/check_spec_consistency.py` version bump sweep.

### Out of scope

1. `academic-paper/revision` mode.

2. `academic-pipeline` orchestrator-level contract.

3. External `academic-paper-reviewer` skill integration; it already received reviewer contracts in v3.6.2 and is zero-touch in v3.6.6.

4. Internal/external two-reviewer merge. This is known technical debt and remains a v3.7.x follow-up.

5. New evaluator agent file; `peer_reviewer_agent.md` is the evaluator.

6. Schema 14. Schema 13.1 is the approved backward-compatible add.

7. New CLI flag, contract negotiation UI, or runtime contract editing.

8. Real retracted-paper fixtures or hard FNR/FPR calibration gates.

### Design goals

1. **Mirror v3.6.2 pattern** — schema evolution is backward-compatible, validator structure stays familiar, templates live under `shared/contracts/`, and the load-bearing runtime behavior is a two-call paper-blind/paper-visible hard gate.

2. **Evaluator anti-drift** — `peer_reviewer_agent` commits its contract paraphrase, scoring plan, and disagreement-handling plan before reading the full draft.

3. **Writer pre-commitment** — `draft_writer_agent` commits acceptance criteria and pre-commitment artifacts before drafting against the full paper context.

4. **Cross-model compatible via existing env pattern** — v3.6.6 supports cross-model/cross-runtime comparison through `ARS_CROSS_MODEL` without changing default same-model behavior when unset.

5. **Open-ended task evidence discipline** — A/B evidence uses process metrics and deltas, not absolute claims that a generated paper is objectively good.

### Non-goals

- Do not set an absolute paper-quality threshold; contract-on/off delta is the signal.

- Do not introduce contract negotiation protocol; inherit fixed baseline template + bounded `agent_amendments` append slot from v3.6.2.

- Do not change current Accept/Minor/Major/Reject verdict mapping.

- Do not merge, replace, or coordinate the internal `peer_reviewer_agent` with the external `academic-paper-reviewer` skill.

### Known limitations

- `academic-paper` still has an internal `peer_reviewer_agent`, while the repository also has the external `academic-paper-reviewer` skill. v3.6.6 documents this as known technical debt and leaves merge/routing decisions to v3.7.x.

### Notes for next review round

- §5 must verify whether existing `academic-paper` orchestration already supports separate paper-blind and paper-visible calls. If not, v3.6.6 must include the concrete orchestration change rather than treating the split as a prompt-only edit.

- §3 must spell out the `pre_commitment_artifacts` field shape (subfields, validation rules) — currently named but not structurally specified.

- §6 A/B evidence ship thresholds (+20 pp / 15% / +2 findings) are initial estimates from codex sanity check. Final values to be tuned after fixture sizing in §6.

### 2.2 Codex round-1 design corrections (D1-D4)

After §1 was drafted from Q1-Q7, a codex sanity check on §1 surfaced four design-level issues that survived clarification because they only become visible when the spec meets the existing schema and protocol. All four were applied to §1 and shape §3-§6.

| # | Issue codex surfaced | Decision | Consequence |
|---|----------------------|----------|-------------|
| D1 | Schema 13 has reviewer-specific **required** fields (`measurement_procedure.reviewer_must_output_before_paper`, `failure_conditions[].cross_reviewer_quantifier`, editorial enum on `failure_conditions[].action`). A bare `mode` enum addition will fail validation for `writer_full` / `evaluator_full`. The "13.1 simple add" framing was too optimistic. | **Apply v3.6.2's `allOf` / `if mode startsWith reviewer_` conditional pattern to all four reviewer-specific fields.** Mirror the technique v3.6.2 already used for `cross_reviewer_quantifier` (v3.6.2 spec §3.3). | §3 specifies four reviewer-conditional gates (not one). Existing reviewer contracts validate identically (zero-touch promise preserved). New writer/evaluator contracts are unaffected by reviewer-specific fields. |
| D2 | `disagreement_handling` was originally proposed as a single field for both writer and evaluator. But "disagreement" is meaningless for a solo writer (no peer to disagree with). | **Split into two fields.** Writer mode requires `pre_commitment_artifacts` (what to commit pre-paper). Evaluator mode requires `disagreement_handling` (how to resolve writer-evaluator disagreement). Each gated to its respective mode. | Schema 13.1 adds two optional top-level fields, not one. Two new conditional gates: `if mode == writer_full` requires `pre_commitment_artifacts`; `if mode == evaluator_full` requires `disagreement_handling`. |
| D3 | "Cross-model by default" framing in original Design Goal 4 contradicts the actual decided behaviour (Q3: unset → same-model with warning, set → cross-model). The framing inflated the truthful claim. | **Reword Design Goal 4 to "Cross-model compatible via existing env pattern."** Truthful framing matches actual behaviour. | Design Goal 4 in §1 reflects the change. README / CHANGELOG sweep (in-scope 13) carries the same wording so no claim of "default cross-model" reaches users. |
| D4 | Codex P2 #18 flagged that `agreement_audit.md` placed under `academic-paper/references/` mixes versioned source with runtime artifact, and recommended splitting protocol-doc from runtime-output. Reading that finding against v3.6.2's contract philosophy raised a deeper question: should `agreement_audit` be a **schema field** at all? Agreement-audit data is observed during the run, not pre-registered acceptance criteria (the v3.6.2 contract definition). Embedding observed data in the schema violates v3.6.2's load-bearing principle that contract = "what good looks like before the work runs". | **Extension of codex's P2 #18 finding (not codex's own recommendation):** remove `agreement_audit` from schema entirely. Keep only the protocol document (versioned, in `academic-paper/references/agreement_audit_protocol.md`) and runtime example output (in `examples/ab_evidence/v3.6.6/agreement_audit_results.md`). Audit data lives in runtime artifacts, never in the contract. | §1 in-scope item 1 lists only two new optional schema fields. The audit/runtime separation appears in in-scope item 10 (split-path delivery). Note that codex's original recommendation only addressed file location (split protocol from runtime output); the schema-removal decision is one step further. |
