# Academic Research Skills - GitHub Copilot Instructions

## Project Overview
This is a comprehensive suite of Claude Code skills for academic research, covering the full pipeline from research to publication. It integrates AI assistance into the academic writing and research workflow while maintaining human oversight.

## Key Principles
1. **Human-in-the-loop**: AI augments the researcher, not replaces them
2. **Quality over automation**: Focuses on handling grunt work (references, formatting, verification) so humans can focus on substantive work
3. **Integrity gates**: Multiple validation checkpoints prevent common AI failure modes
4. **Transparency**: All AI-assisted work is clearly documented and auditable

## Main Features

### Deep Research
- 13-agent research team with Socratic guided mode
- PRISMA systematic review support
- Intent detection and dialogue health monitoring
- Cross-model DA capabilities
- Semantic Scholar API verification

### Academic Paper Writing
- 12-agent paper writing pipeline
- Style Calibration (learns user's writing style)
- Writing Quality Check (detects AI-generated patterns)
- LaTeX hardening and visualization
- Citation verification and conversion
- Anti-leakage protocol

### Academic Paper Reviewer
- 7-agent multi-perspective peer review
- 0–100 quality rubrics
- Dynamic reviewers and Devil's Advocate perspective
- R&R traceability matrix
- Read-only constraint enforcement

### Academic Pipeline
- 10-stage orchestrated pipeline
- Adaptive checkpoints
- Claim verification
- Material Passport tracking
- Score trajectory tracking

## Development Guidelines

### Code Style
- Follow Python/JavaScript conventions used in the project
- Use clear, descriptive variable and function names
- Document complex logic with comments
- Include type hints where applicable

### When Contributing
1. Respect the human-in-the-loop principle
2. Ensure all new agents declare `data_access_level` and `task_type`
3. Add integrity checks for critical operations
4. Test against the validation gates
5. Update relevant documentation

### Data Access Levels
- `raw`: Direct access to user data
- `redacted`: Anonymized/masked data access
- `verified_only`: Only verified, audited data

### Task Type Annotation
- `open-ended`: Tasks without clear correct answers
- `outcome-gradable`: Tasks with measurable outcomes
