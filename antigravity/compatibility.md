## ARS on Antigravity: compatibility rules

ARS was written for Claude Code. Its files are used unmodified from `{root}`. Apply these translations for the whole ARS task.

1. **Read whole files.** Antigravity loads only the first 24,000 bytes of a skill body, and the ARS skill files are larger. Whenever ARS tells you to load a skill, mode, agent prompt, reference, protocol, or template, read that file from disk to its last line before acting on it. A partial read is a loading failure: report it and stop.
2. **Paths.** `${CLAUDE_PLUGIN_ROOT}` is `{root}`. Repository-root paths (`shared/`, `scripts/`, `docs/`, `MODE_REGISTRY.md`) resolve against `{root}`, and skill-relative paths (`references/`, `agents/`, `templates/`, `examples/`) against that skill's directory under `{root}`. Neither resolves against the user's project directory. Run ARS utility scripts by absolute path (`python3 {root}/scripts/<name>.py`) with the user's project as the working directory.
3. **Tools.** A Claude tool name means the equivalent tool available here: Read is `read_file`; Write, Edit and MultiEdit are `write_file` and `edit_file`; Bash is `run_command`; AskUserQuestion is `ask_question`; WebSearch is `search_web`; WebFetch is a page-fetch tool if you have one, otherwise an HTTP request through `run_command`. "Invoke the Skill tool with `academic-research-skills:<skill>`" means: read `{root}/<skill>/SKILL.md` in full and follow it.
4. **Agents.** Where ARS dispatches a specialist agent (Task or Agent tool, subagent, parallel reviewers), dispatch a real subagent (`invoke_subagent`, defining it with `define_subagent` if needed) whose instructions are the complete agent prompt file under `{root}` and whose input is only what ARS says that role receives. If you run a role inline in this context instead, say so in the deliverable: an inline role is not an independent or isolated review. Claude `model:` hints (opus, sonnet) do not apply; the session model is used.
5. **Citation verification is not optional.** Run every verification, integrity, and citation-existence step ARS specifies, with a web tool or `run_command`. Give a DOI or URL for each cited work. Do not describe a reference as verified unless you checked it against a bibliographic source in this run; mark the others as unverified. Report what was actually done: name the source each reference was checked against, and state how much of each work you read (search snippet, abstract, or full text); never report a full-text read of a work you did not open. If no web capability works, state that verification did not run.
6. **AI-use disclosure.** Produce every AI-use disclosure ARS specifies. Name the model actually in use and Antigravity as the platform, and list each degraded item from rules 4, 5 and 7 that applied to this run.
7. **No write-scope guard.** The ARS `PreToolUse` write-scope hook does not run on Antigravity. ARS Phase Boundary rules are enforced only by you: write only where the current phase allows, and never modify anything under `{root}`.
8. **Checkpoints.** Human checkpoints are unchanged. Wherever ARS says to stop for the user's decision, stop and wait; do not continue on the user's behalf.
