# 中文 AI 排印指纹

`HUANGFU_2026_FRAMEWORK.md` 处理"词法"维度的 AI 味。本文件处理另一族：**排印指纹**。这些标记不在皇甫博媛论文的语料编码里，但都属于大陆中文读者（尤其编辑岗位）一眼就能识别的"这是 AI 写的"信号。

## 已识别的三类排印指纹

### 一、破折号 `——` / `—`（CRITICAL，hard gate）

详见 `EMDASH_PLAYBOOK.md` 与 `VERIFICATION_PROTOCOL.md`。简言之：LLM 中文输出大量用 `X——Y（其展开）` 模板，密度远超本世纪前的中文学术写作。在大陆中文学术稿里破折号 = 0 是 hard gate。

### 二、日文 / 港台引号 `「」` `『』`（CRITICAL，hard gate）

**符合标准的依据**：国家标准 GB/T 15834-2011《标点符号用法》规定大陆出版物双引号用 `""`（U+201C/U+201D）、单引号用 `''`（U+2018/U+2019）。`「」` `『』` 不在国标列表内，是日文 / 港台繁体的体例。

**为什么是 AI 指纹**：ChatGPT / Claude 等 LLM 在中文输出中大量使用 `「」`，跟训练数据里日文 / 繁体内容的权重相关。大陆读者（尤其编辑、出版、记者岗位）看到 `「」` 已经形成"这是 AI 写的"直觉信号。

**修复**：

- 替换为 `""`（双引号）或 `''`（单引号）
- 或直接删除：学术中文里术语只在首次引入 / 直接引用 / 表反讽时打引号；多数 `「术语」` 可以直接写成 `术语`

### 三、引号密度 ` "" ` 过高（MINOR / MAJOR，非 hard gate）

**核心洞察**：即使全部用了正确的中文弯引号 `""`，**密度过高本身就是 AI 味**。

**为什么**：

- 学术中文里引号有三种合法用法：首次引入新术语 / 直接引用他人 / 表反讽或保留。这三种之外的引号都是冗余。
- LLM 习惯把每个技术词都框起来：`"AI 味""破折号""程式化""松弛"……` 每个概念都打引号。
- 这种"术语标注 tic"读起来居高临下：等于在告诉读者 `你看这是个术语啊你别没看见`，隐含对读者的低估。
- 真正的学术写作里，术语只在第一次出现时打引号定义，后续直接使用。

**密度阈值（pairs per 1000 visible CJK chars）**：

| 密度 | 严重度 | 含义 |
|------|-------|------|
| ≤ 10 | OBSERVATION | 正常 |
| 10-16 | MINOR | 偏多，建议删一些 |
| > 16 | MAJOR | 明显过密，每个术语都在打引号 |

**修复**：

- 全文搜 `""`，对每对问自己：这是首次引入吗？是直接引用吗？是反讽吗？三个都不是就删
- 特别留意"概念-列表式"段落，例如 `本文识别"X""Y""Z"三个维度`，可以改写为 `本文识别 X、Y、Z 三个维度`（把它们当熟词用）

## 跟其它 skill 的关系

本族指纹只在中文段落里检测：

- `latex-paper-en` 处理英文论文，本规则不适用
- 英文摘要、英文参考文献条目 即使在中文论文里 也不计入（英文用 `"..."` 或 `'...'` 是英文体例的事）

`check_corner_brackets` 与 `check_quote_density` 都按段落判断：是否含 CJK 字符。

## 实战参考（2026-05-17）

清扫一份南大编辑出版学硕士论文（全文 6400 字、共 104 段）时：

- 破折号：101 处 → 0（按 EMDASH_PLAYBOOK 7 种模式替换）
- `「」`：0（论文文档本身无此问题，但用户的 AI 对话伙伴在跨会话讨论中大量出现，是另一回事）
- 弯引号密度：21 对 / 千字（132 pairs / 6300 chars），命中 MAJOR 阈值

用户对话原话："还有要少用 `「」`，但是我不知道这个是为什么，你来揣测一下。" 揣测后她确认三层原因都对：地域排印传统不匹配 + LLM 输出指纹 + 引号密度过高（学术中文里每个术语都打引号读起来居高临下）。三层中 #3 是最深层原因，#1 #2 是它的形式载体。

## 处理优先级

1. `「」` `『』` 全替换为 `""` 或 `''`（hard gate，必须为 0）
2. 全文 `""` 密度 > MAJOR 时，按 SKILL.md 推荐的 playbook 流程逐对审核，能删则删
3. 跟破折号一起，这一族构成 `aiwei-zh` 的"中文 AI 排印指纹"完整门控
