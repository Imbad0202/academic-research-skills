# 破折号上下文替换 Playbook

## 为什么不能一律换成冒号

中文学术稿里发现 50+ 个破折号时，直觉的修法是"全部换成冒号"。这样做的代价：

- 原本"X——Y" 的模板被"X：Y" 的模板替换，本质上换了一种 AI 痕迹
- 一段里出现 3 个以上"X：Y" 结构本身就触发`HUANGFU_2026_FRAMEWORK.md` §"完美对称结构" 的告警
- 失去节奏变化

正确做法：每个破折号按上下文分类，从下表中选最合适的替换。整篇下来标点会自然散开，节奏不一律，反而读起来"像人写的"。

## 7 种模式 → 替换决策表

| 编号 | 上下文模式 | 原文示例 | 替换标点 | 替换后示例 |
|------|----------|---------|---------|----------|
| **P1** | 复合名词链 | "作者—编辑—读者"、"规约—审核—记忆—工具"、"input—process—output" | **顿号** `、` | "作者、编辑、读者" |
| **P2** | 问题 / 列表正式引入 | "他提出了一个尖锐的问题——倘若 X，那么 Y？" | **冒号** `：` | "他提出了一个尖锐的问题：倘若 X，那么 Y？" |
| **P3** | 平行续接（前后是一个完整动作） | "依赖编辑的体现化经验——一位资深编辑对稿件的判断是数十年积累的" | **句号** `。` | "依赖编辑的体现化经验。一位资深编辑对稿件的判断是数十年积累的" |
| **P4** | 同位语 / 定义展开 | "需要先承认一个事实——出版业从未是无挽具的行业" | **逗号 + 即** `，即` | "需要先承认一个事实，即出版业从未是无挽具的行业" |
| **P5** | 例子 / 补充说明 | "确实优于传统人审——例如对引文准确性的核查" | **逗号** `，` | "确实优于传统人审，例如对引文准确性的核查" |
| **P6** | 解释性补充（前文抽象，后文具体） | "更可见——每一条审核规则都写在文件里" | **冒号** `：` | "更可见：每一条审核规则都写在文件里" |
| **P7** | 英文括号化插入语 | "publishing—X, Y, Z—into the stage" | **圆括号** `(...)` | "publishing (X, Y, Z) into the stage" |

## 如何决定用哪种

按这个判断顺序：

1. **破折号两侧是不是名词链？** → P1，用顿号
2. **后面是不是一个英文括号化插入语，两个破折号成对？** → P7，用圆括号
3. **后面是不是一个问题、列表、或正式引入的具体内容？** → P2 或 P6，用冒号
4. **后面是不是同位语展开，能用"即"自然接？** → P4，用"，即"
5. **后面是不是举例？** → P5，用逗号
6. **后面是不是一个独立完整的句子？** → P3，用句号
7. **以上都不像** → 默认逗号 `，`，让句子流动

## 反例：以下做法会造出新模板

❌ **一律换成冒号** —— 见上文。
❌ **一律换成句号** —— 短句过密，节奏断碎。
❌ **一律换成逗号** —— 长句过长，丢失停顿层级。
❌ **机器替换 + 不读上下文** —— 最常见的失败：把 "作者—编辑—读者" 换成 "作者：编辑：读者"。

## 平行结构（"其一/其二/其三"）的特殊处理

文档里出现连续 3 条"其 N，X——Y" 时，三个破折号都要换。

正确做法（来自 2026-05-17 实战）：**故意打散**。

例：原文三条都用 ——

```
其一为开放与可预测的张力——Harness 必须允许 Agent 处理多样化的稿件类型...
其二为编辑自主与流程规范的张力——Harness 试图把编辑的判断显式化为可执行规则...
其三为创作生成与出版稳定的张力——Agent 在每次会话中可能产出新的判断...
```

打散后（混用 逗号 / 句号 / 逗号）：

```
其一为开放与可预测的张力，Harness 必须允许 Agent 处理多样化的稿件类型...
其二为编辑自主与流程规范的张力。Harness 试图把编辑的判断显式化为可执行规则...
其三为创作生成与出版稳定的张力，Agent 在每次会话中可能产出新的判断...
```

**为什么打散**：保留三联的语义平行（仍然是"其一/其二/其三"枚举），但破开节奏的完美对称。读起来像"作者写到第二条时思路变了一下"，正是"瑕疵 = 活人感"的小细节。

## "结构化" 等技术词不要顺手改

发现 "结构化的约束与反馈" 时，不要因为"结构化"在 `HUANGFU_2026_FRAMEWORK.md` 是 AI 味标记就改写。在 Harness / 数据 / 工程 / 算法语境，"结构化" 是中性技术术语，是论文的核心概念词。

判断方法：把"结构化"换成"系统化"或"组织化"读一遍，如果意思变了或学术准确性下降，就保留原词。如果意思不变，那确实是空泛 AI 修饰，可以换。

## 实战参考

2026-05-17 在一份 6300 字的中文出版学论文（dizzy 的硕士论文）中：

- 原始破折号：101 处（44 对 —— + 13 单 —）
- 按本 playbook 替换后：0 处
- 顿号替换：4 处（P1）
- 圆括号替换：4 处（P7，英文摘要）
- 冒号：14 处（P2、P6）
- 句号：13 处（P3）
- 逗号：12 处（P5、默认）
- "，即"：3 处（P4）

标点分布散开，没有形成新的"X：Y" 或"X，即 Y" 模板密度告警。
