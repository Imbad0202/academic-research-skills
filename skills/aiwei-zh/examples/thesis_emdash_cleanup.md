# 案例：硕士论文“机器三审”破折号清扫与 AI 味整稿验收

本案例是 2026-05-17 在一位南京大学编辑出版学研究生的硕士论文上的真实工作流，用于说明本 skill 的两个核心场景：

1. 章节合并 / 嫁接后的整稿验收（避免"只验润色段"的常见事故）
2. 上下文敏感的破折号替换（避免一律换成冒号造出新模板）

## 论文背景

- 题目：《机器三审：Harness 工程化对现代出版业的理论冲击与省思》
- 字数：约 6300 字（中文正文部分）
- 章节：1 引言 / 2 文献回顾 / 3 把 Harness 作为出版基础设施 / 4 理论冲击 / 5 结语
- 之前的修订：§2.1 / §2.2 / §4.3 / §5 已经过四轮迭代润色（标记词频已优化、A1/A2/A3 文献综述检查已通过）

## 失败现场

四轮润色完成后，把润色稿（`04_文献回顾与结语_润色稿.docx`，44 KB，仅含 §2 / §4.3 / §5）合并回原稿骨架，产出 `05_全文_润色合并版.docx`（27 KB，全文 104 段）。

宣布"验收通过"。被作者当场指出：

> "你是不是忘了一件事情，我说最好不要用破折号？"

用本 skill 重新跑：

```bash
$ uv run python scan_aiwei.py --mode gate 05_全文_润色合并版.docx

**Mode**: gate
**Gate result**: FAIL
**Findings**: 82
## CRITICAL (53)
...
```

53 个 CRITICAL 破折号——全部来自未润色章节（§1、§3、§4.1-4.2、§4.4），从 `00_原稿.docx` 继承。润色时只检查了新写/改的段落，没有对整稿 grep `—`。

## 修复：7 种模式的破折号替换

按 `references/EMDASH_PLAYBOOK.md` 分类。完整论文里 50 次替换的分布：

| 模式 | 出现次数 | 替换标点 | 案例 |
|------|---------|---------|------|
| P1 复合名词链 | 4 | 顿号 `、` | `"作者—编辑—读者"` → `"作者、编辑、读者"` |
| P7 英文括号 | 4 | 圆括号 | `publishing—X, Y, Z—into` → `publishing (X, Y, Z) into` |
| P6 解释性补充 | 8 | 冒号 `：` | `更可见——每一条审核规则` → `更可见：每一条审核规则` |
| P2 问题引入 | 6 | 冒号 `：` | `提出了一个尖锐的问题——倘若 X` → `提出了一个尖锐的问题：倘若 X` |
| P3 平行续接 | 13 | 句号 `。` | `体现化经验——一位资深编辑` → `体现化经验。一位资深编辑` |
| P5 例子引入 | 6 | 逗号 `，` | `优于传统人审——例如对引文` → `优于传统人审，例如对引文` |
| P4 同位语展开 | 3 | `，即` | `承认一个事实——出版业从未` → `承认一个事实，即出版业从未` |
| 默认连接 | 6 | 逗号 `，` | `核心机制——它通过结构化` → `核心机制，它通过结构化` |

注意标点分布：冒号 14、句号 13、逗号 12、顿号 4、圆括号 4、`，即` 3。**没有任何一种标点占绝对多数**，这是有意打散的结果。如果都换成冒号（最直观的修法），论文里会出现一段中 3+ 个冒号 `X：Y` 的密集模板，触发 `HUANGFU_2026_FRAMEWORK.md` 的完美对称告警。

## 三联排比的特殊处理

§3.3 三重张力段原文：

> 其一为开放与可预测的张力——Harness 必须允许 Agent 处理多样化的稿件类型...
> 其二为编辑自主与流程规范的张力——Harness 试图把编辑的判断显式化...
> 其三为创作生成与出版稳定的张力——Agent 在每次会话中可能产出新的判断...

直觉修法（全换冒号或全换句号）会保留"完美三段式"AI 痕迹。本 skill 推荐的修法是**故意打散**：

> 其一为开放与可预测的张力，Harness 必须允许 Agent 处理多样化的稿件类型...
> 其二为编辑自主与流程规范的张力。Harness 试图把编辑的判断显式化...
> 其三为创作生成与出版稳定的张力，Agent 在每次会话中可能产出新的判断...

混用逗号 / 句号 / 逗号。三联的语义平行保留，但节奏不对称，读起来像"作者写到第二条时停顿了一下"。这就是论文里"瑕疵 = 活人感"的工程实现。

## 验收

修复后再跑 gate：

```bash
$ uv run python scan_aiwei.py --mode gate 05_全文_润色合并版.docx
# aiwei-zh report
**Mode**: gate
**Gate result**: PASS
**Findings**: 3

## MINOR (3)
- `[Script]` **throat_clearing** @ paragraph 42: 段首清嗓子 "值得注意的是"
- `[Script]` **perfect_symmetry** @ paragraph 27: 段内出现 3 个冒号 "X：Y" 结构
- `[Script]` **perfect_symmetry** @ paragraph 53: 段内出现 3 个冒号 "X：Y" 结构
```

PASS。剩余 3 个 MINOR：

- Paragraph 42 的 "值得注意的是" 是原稿继承的清嗓子，未在本轮润色范围。
- Paragraph 27 和 53 的 3 个冒号是上一步破折号替换造成的——这恰好印证了"不能一律换冒号"的预警。下一轮可以把其中 1 个改成句号或重写。

## 教训

1. **润色范围 ≠ 验收范围**。任何整稿交付物必须 grep `—` 验证。这是 hard gate，不可商议。
2. **替换决策本身需要分类**。一律替换会造新模板，比保留破折号更隐蔽。
3. **节奏不对称是工程而非随机**。三联排比可以保留语义平行，但要主动打散标点。
4. **scanner 会标出你自己造的新问题**。如本案例 P27、P53——上一步修了 100 个破折号，造出 2 个冒号密度告警。迭代检查是必要的。
